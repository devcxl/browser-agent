# ADR: 会话消息归属与历史载入判定

- **日期**: 2026-10-31
- **状态**: Implemented（随 React 19 升级落地）
- **相关**: `src/entrypoints/sidepanel/ChatContext.tsx`、`src/entrypoints/sidepanel/__tests__/ChatContext.test.tsx`

---

## 背景

升级 React 19 后，侧边栏出现一处真实回归：**会话刚创建就发消息时，用户的第一条消息会被空历史覆盖**。

原实现用「载入期间消息版本号是否变化」判断能否用历史覆盖当前展示的消息：

```ts
const messageVersionAtLoadStart = messageVersionRef.current;
// 载入完成时：版本号没变 → 用历史覆盖；变了 → 保留当前消息
```

这个判定依赖 **effect 与乐观消息的先后顺序**：React 18 下会话切换的 effect 先跑（版本号起点为 0），
乐观消息后到（版本号变为 1），载入完成时发现版本号变了 → 保留乐观消息。React 19 改变了
异步回调里的 setState 与 effect 的交错顺序，乐观消息可能**先于**载入 effect 到达，
版本号起点与结束值相同 → 历史（此时还是空的）直接覆盖乐观消息。

实测（React 19.3.1 + @testing-library/react 16.3.3）下
`ChatContext.test.tsx` 中两条「不覆盖快速消息」的用例失败，与上面的分析一致。

## 决策

**改用「消息归属会话」判定，不再用版本号比较。**

1. 每条展示中的消息记录它属于哪个会话（`messageOwnersRef`: message id → 会话 id）：
   - 来自 Agent 的消息按 **Agent 运行所在的会话**归属（Agent 回调携带 conversationId），
     不用“用户当前查看的会话”——否则运行中切会话会把消息写到新会话名下；
   - 归属一旦登记就不再改写：流式更新会重复提交同一条消息，
     每次重写会让归属随“当前查看的会话”漂移；
   - 没有活跃会话时添加的消息视为「未归属」，载入时归入正在载入的会话，
     并当场认领归属，避免它在下一次切换时继续冒充本会话的消息。
2. 载入会话 C 的历史完成时：
   - **合并**：历史在前（更早），尚未落库的内存消息在后；
   - 同 id 只留历史版本（它已是落库后的最终形态）——为此，Agent 侧持久化用户
     消息时复用 UI 侧生成的 id（`AgentRunInput.userMessageId`），否则同一条用户
     消息会有两个 id，历史与内存消息无法去重；
   - 其他会话的条目留在状态里但不展示。
3. 载入失败时：属于 C 的消息存在就保留且不报错，否则报错并清空。
4. 不属于当前会话的消息不展示：Agent 在别的会话产出的消息不会串到当前会话。
5. 消息与加载错误放在同一份状态里：载入成功/失败的判定必须在同一份最新状态上
   完成，避免“读上一帧快照”导致刚到达的消息被清掉、或误报加载失败。
6. 不在渲染期写 ref：归属与过滤使用 `addMessage` 闭包里的 `activeId`（回调每次
   渲染都会重新注册，闭包始终是最新一次已提交渲染的值）；未归属消息的认领放在
   独立的 effect 里（提交后执行），不在状态更新函数里产生副作用。

历史消息在装载时同样登记归属，保证「切走再切回」时不会把上一个会话的残留留在界面上。

## 理由

- 判定依据从「时序」变成「归属」，不再依赖 React 的调度顺序，React 18/19 行为一致。
- 归属是消息自身的属性，不依赖 effect 与 setState 的相对时序，跨版本稳定。
- 顺带修掉一个既有缺陷：切换会话时，上一个会话的残留消息不再短暂挂在新会话下。

## 已知限制

- 助手消息与工具消息的乐观 id 与落库 id 仍不同（Agent 侧每条助手消息另生成
  `crypto.randomUUID()`），因此“历史与内存消息同时包含同一条助手消息”的极端时序下
  可能出现重复；用户消息已通过 id 对齐消除该问题。
- 消息归属表随会话生命周期增长，当前未做清理（每会话消息量级下可接受）。
- `tsconfig.json` 排除 `src/entrypoints`，本改动不在 `tsc` 覆盖范围内（靠测试与
  lint 保证）；若把该目录纳入类型检查，会新增约 27 处非测试源码的类型错误，
  属独立任务。

## 后续行动

- 助手/工具消息的 id 也统一（Agent 侧持久化时复用 UI 侧 id），彻底消除极端时序下
  的重复可能。
