# ADR: 会话消息归属与历史载入判定

- **日期**: 2026-10-31
- **状态**: Implemented（随 React 19 升级落地）
- **相关**: `src/entrypoints/sidepanel/ChatContext.tsx`、`src/entrypoints/sidepanel/__tests__/ChatContext.test.tsx`

---

## 背景

升级 React 19 后，侧边栏出现一处真实回归：**会话刚创建就发消息时，用户的第一条消息会被空历史覆盖**。

原实现用「载入期间消息版本号是否变化」判断能否用历史覆盖当前展示的消息：

```ts
const messageVersionAtLoadStart = messageVersionRef.current;
// 载入完成时：版本号没变 → 用历史覆盖；变了 → 保留当前消息
```

这个判定依赖 **effect 与乐观消息的先后顺序**：React 18 下会话切换的 effect 先跑（版本号起点为 0），
乐观消息后到（版本号变为 1），载入完成时发现版本号变了 → 保留乐观消息。React 19 改变了
异步回调里的 setState 与 effect 的交错顺序，乐观消息可能**先于**载入 effect 到达，
版本号起点与结束值相同 → 历史（此时还是空的）直接覆盖乐观消息。

实测（React 19.3.1 + @testing-library/react 16.3.3）下
`ChatContext.test.tsx` 中两条「不覆盖快速消息」的用例失败，与上面的分析一致。

## 决策

**改用「消息归属会话」判定，不再用版本号比较。**

1. 消息以 `{ msg, owner }` 存放，`owner` 是 Agent 运行所在的会话，**不是**用户当前查看的会话：
   - `addMessage(msg, conversationId)` 的 `conversationId` **必填**。归属不能靠
     “当前查看的会话”反推——省略它就会把消息判到与它无关的会话名下；
   - 同一条消息的流式更新只替换内容，不重算归属（否则归属会随查看会话漂移）；
   - 展示 = `owner` 等于当前会话的条目：别的会话在跑的消息不会串到当前会话。
2. 内存里只保留 **当前会话 + 运行中会话** 的消息，其余以数据库为准（离开即丢、回来重载）：
   - 侧边栏是长期存活页面，留着副本会让每次流式更新都拷贝与累计历史等量的数据；
   - 助手/工具气泡落库后 **id 会变**（Agent 侧另生成 UUID），内存旧副本与历史无法按 id 去重，
     所以「切走再切回」若保留副本就会把同一条回复渲染两次 —— 用丢弃规避；
   - 运行中的会话不重载历史：历史里已包含当前这轮的部分输出，重载会多出一份。
3. 载入会话 C 的历史完成时：历史在前（更早），**载入期间新到且尚不可能落库**的消息在后；
   - 用户消息在历史里按 id 去重（`AgentRunInput.userMessageId`：UI 生成 id，Agent 落库复用），
     否则同一条用户消息会有两个 id；
   - 仍在输出（`streaming`/`running`）的助手/工具气泡按状态保留；
   - 载入失败时：属于 C 的消息存在就保留且不报错，否则报错并清空。
4. 消息与加载错误放在同一份状态里：载入成功/失败的判定必须在同一份最新状态上完成，
   避免“读上一帧快照”导致刚到达的消息被清掉、或误报加载失败。
5. 不在渲染期写 ref，也不在 setState 更新函数里产生副作用。

## 理由

- 判定依据从「时序」变成「归属 + 是否可能已落库」，不再依赖 React 的调度顺序，React 18/19 行为一致。
- 归属是消息自身的属性，不依赖 effect 与 setState 的相对时序，跨版本稳定。
- 顺带修掉一个既有缺陷：切换会话时，上一个会话的残留消息不再短暂挂在新会话下。

## 已知限制

- 助手/工具气泡的乐观 id 与落库 id 不同，因此 **重载历史时不能保留已输出的助手条目**：
  当前靠“只保留 streaming/running 的气泡”规避。若补上助手消息的 id 对齐
  （`onStepFinish` 把预生成的 id 传给 UI），这条限制即可消除，判定也能简化为纯 id 去重。
- 内存中最多保留「当前会话 + 运行中会话」两份消息，规模由单个会话的消息量决定。
- `tsconfig.json` 排除 `src/entrypoints` 与 `src/content`，本改动不在 `tsc` 覆盖范围内（靠测试与 lint 保证）。
  把这两条路径纳入类型检查会暴露 89 处非测试源码错误（`src/entrypoints` 25 处、
  `src/content` 64 处，后者集中在 grokbot 的 PixiJS 几何运算）；其中 `src/entrypoints`
  那批里已有真实缺陷（如 #252 引入的 `SettingsPanel` 未解构 `onSaveAgentSettings`、
  未 import `exportFullSnapshot`），属独立任务。
